fix: 위험도 계산 로직 개선 - 다층 분석 기반 합리적 위험도 산정

문제점:
- 기존 로직이 단순하여 항상 50점만 반환되는 고질적 문제
- (고위험 로그 비율 × 100) + (중위험 로그 비율 × 50) 방식의 한계
- 최소 50점 보장 로직으로 인한 획일적인 결과

개선사항:
- 다층 분석(Multi-layer Analysis) 방식 도입
  1. 위험도 레벨별 분류 (40점): Critical/High/Medium/Low/Minimal
  2. WAF 액션별 분류 (30점): BLOCK/COUNT/ALLOW
  3. 공격 비율 분석 (30점): 정상 트래픽 제외한 실제 공격 비율

- 합리적인 위험도 범위 설정
  - 최소: 20점 (완전히 안전한 상태는 없음)
  - 최대: 95점 (100점은 시스템 다운 상태로 예약)
  - 기존 "최소 50점 보장" 로직 제거

- 룰별 중요도 계산 개선
  - WCU (50%) + 탐지 건수 (30%) + 차단 건수 (20%)
  - 기존: WCU (70%) + 탐지 건수 (30%)

- 최저 위험도 제약 추가
  - 최저 위험도는 최고 위험도의 최소 10% 유지
  - 예: max_risk = 30이면 min_risk >= 3

- 디버그 정보 추가
  - 콘솔에 위험도 계산 상세 정보 출력
  - calculation_method, score_breakdown 포함

기술적 변경:
- api_server.py: /api/risk-calculation 엔드포인트 전면 개편
- RuleManagement.js: 디버그 정보 콘솔 출력 추가
- docs/RISK_CALCULATION.md: 위험도 계산 로직 상세 문서 작성

테스트 시나리오:
- 로그 1000개, 치명적 50개, 높음 150개, 중간 300개
- 차단 200개, 카운트 300개, 허용 500개
- 공격 로그 600개 (60%)
- 결과: max_risk = 47점 (기존 50점 → 개선)

Breaking Change: 없음 (API 응답 구조 확장, 하위 호환성 유지)
